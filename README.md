# Notebook — Telegram-бот онлайн-записи

Публичный учебный репозиторий фиксирует результат двух завершённых задач команды.
Проект запускается на Python и Aiogram, а данные текущей версии сохраняются в JSON.
Файлы будущих модулей уже расположены по архитектуре и содержат краткое описание
своего назначения, но их пользовательские сценарии пока не реализованы.

## Что работает сейчас

- команда `/start` и возврат на главный экран;
- разделы «Мои записи» и «Мои специалисты» в главном меню;
- динамический список из одного или двух бизнесов пользователя;
- создание не более двух независимых бизнесов;
- просмотр профиля бизнеса мастером и клиентом;
- клиентская deep-link ссылка на профиль бизнеса;
- поиск специалиста по публичному коду;
- добавление и удаление специалиста из избранного;
- включение и отключение приёма новых записей;
- изменение основных настроек бизнеса;
- сохранение пользователей, бизнесов и избранного в JSON между перезапусками.

Кнопки услуг, расписания, календаря, записей и уведомлений показывают сообщение о
будущей реализации. Их файлы оставлены архитектурными заготовками.

## Задача 1 — главное меню и профиль бизнеса

**Цель:** реализовать Telegram-интерфейс начальной навигации и управления бизнесом.

**Файлы результата:**

- `src/notebook_bot/bot/menu.py`;
- `src/notebook_bot/bot/business.py`.

**Выполнено:**

1. Обработана команда `/start` и callback возврата в главное меню.
2. Создана динамическая inline-клавиатура с разделами «Мои записи»,
   «Мои специалисты» и кнопками бизнесов пользователя.
3. Реализовано отображение одного или двух бизнесов и скрытие создания после
   достижения лимита.
4. Создан пошаговый Telegram-диалог добавления бизнеса.
5. Реализованы просмотр профиля, клиентская ссылка, публичный код и переключатель
   приёма новых записей.
6. Добавлены поиск специалиста по коду и работа с избранными специалистами.
7. Добавлены формы основных и расширенных настроек бизнеса.
8. Переходы к будущим разделам передаются через callback соответствующим роутерам.

**Граница задачи:** эти файлы отвечают за сообщения, кнопки, формы и навигацию.
Получение и сохранение данных выполняются через сервис `Catalog`; Telegram-слой не
читает JSON напрямую.

## Задача 2 — модели данных и временное хранилище

**Цель:** описать данные предметной области и обеспечить работу прототипа без СУБД.

**Файлы результата:**

- `src/notebook_bot/models.py`;
- `src/notebook_bot/storage.py`.

**Выполнено:**

1. Описаны модели пользователя, бизнеса, услуги, недельного расписания и исключения
   конкретной даты.
2. Добавлены модели клиентской карточки, персональной длительности, записи, истории,
   избранного и уведомления.
3. Реализованы универсальные операции `get`, `list`, `put` и `delete`.
4. Добавлено транзакционное изменение копии данных под `asyncio.Lock`.
5. Реализовано чтение и сохранение JSON с версией схемы.
6. JSON записывается во временный файл и атомарно заменяет предыдущую версию, чтобы
   снизить риск повреждения данных при сохранении.
7. Данные разных бизнесов разделяются через `business_id`.

**Граница задачи:** JSON является временным хранилищем прототипа. В будущей версии
его заменит адаптер Microsoft SQL Server с теми же операциями Repository.

## Точка запуска и вспомогательный код

`src/notebook_bot/main.py` собирает приложение, подключает роутеры двух выполненных
задач, middleware и FSM, после чего запускает polling. Неизвестные callback будущих
разделов обрабатываются общей заглушкой и не приводят к падению бота.

`src/notebook_bot/config.py` читает токен, режим хранения, путь к JSON и внутренний
часовой пояс из `.env`.

Для связи двух задач необходимы два вспомогательных модуля:

- `bot/common.py` — общие клавиатуры, отправка сообщений, FSM-формы, middleware и
  обработка ожидаемых ошибок;
- `logic/catalog.py` — минимальный сервис пользователей, бизнесов и избранного;
- `logic/rules.py` — общие проверки текста, чисел, дат, времени и интервалов.

Это интеграционный каркас. Он не относится к будущим сценариям записи, календаря
или SQL Server.

## Архитектура

```text
Пользователь Telegram
        ↓
Telegram Bot API
        ↓
main.py → Aiogram Dispatcher
        ↓
bot/menu.py и bot/business.py
        ↓
logic/catalog.py
        ↓
storage.py
        ↓
data/notebook.json
```

Каталоги имеют следующие границы ответственности:

| Часть | Назначение |
|---|---|
| `bot` | Telegram-команды, callback, сообщения, клавиатуры и FSM |
| `logic` | Сценарии приложения и правила, независимые от Telegram |
| `models.py` | Общие модели предметной области |
| `storage.py` | Временный JSON-адаптер |
| `database` | Будущий адаптер Microsoft SQL Server |
| `main.py` | Сборка зависимостей и запуск приложения |
| `config.py` | Загрузка локальной конфигурации |

## Запуск

Требуется Python 3.12 или новее.

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
python -m pip install -e .
Copy-Item .env.example .env
```

В `.env` необходимо указать новый токен:

```env
BOT_TOKEN=your_new_telegram_bot_token
STORAGE=json
DATA_FILE=data/notebook.json
CITY_TIMEZONE=Asia/Yekaterinburg
BOT_PROXY=system
```

Запуск:

```powershell
python -m notebook_bot.main
```

Файл `.env`, токен и содержимое `data/` не добавляются в Git.

## Проверка результата

1. Отправить боту `/start`.
2. Создать первый бизнес и убедиться, что он появился в меню.
3. Создать второй бизнес и проверить отдельную кнопку каждого бизнеса.
4. Убедиться, что кнопка «Создать бизнес» исчезла.
5. Перезапустить приложение и проверить восстановление бизнесов из JSON.
6. Открыть клиентскую ссылку или найти бизнес по публичному коду.
7. Добавить специалиста в избранное и проверить раздел «Мои специалисты».

## Правило безопасности

Токены Telegram нельзя добавлять в исходный код, README, коммиты или Pull Request.
Если токен был опубликован в сообщении или репозитории, его необходимо отозвать в
BotFather и создать новый.
