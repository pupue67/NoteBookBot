# Кто работает в каких файлах

| Участник | Рабочие файлы | Что передать на проверку |
|---|---|---|
| Задание 1: календарь | `src/notebook_bot/bot/calendar.py`, согласованные изменения в `business.py`, `schedule.py`, `booking.py`, тесты календаря | Один календарь месяца для настройки горизонта, рабочего дня, записи и переноса |
| Задание 2: БД | `src/notebook_bot/database/`, `alembic/`, `tests/database/`, документация настройки | SQL Server-адаптер, миграции, транзакции, ограничения и проверки изоляции |
| Задание 3: публичный ID и поиск | Изменения в `models.py`, `catalog.py`, `business.py`, `storage.py` и тесты поиска | Отдельный публичный ID бизнеса, поиск, ссылка и законченный раздел «Мои специалисты» |
| Команда | Проверка UX, постановка задач, принятие pull request | Проверенный общий результат |

Общие контракты `models.py` и `repository.py` не меняются независимо в разных ветках.
Сначала обсудите изменение в pull request: что меняется, кто использует поле или метод,
как будут обновлены JSON-адаптер, БД и тесты.

Каждый начинает отдельную ветку от актуального `main`:

```text
feature/month-calendar
feature/sql-server-adapter
feature/public-specialist-id
```

Два участника не редактируют один модуль одновременно. Изменения общих моделей,
контрактов, зависимостей и точек подключения предварительно описываются в pull request.
Участник с Write может менять файлы репозитория; изменения проверяются через pull request.
